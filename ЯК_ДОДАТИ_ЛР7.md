# Лабораторна №7 — як додати до поточної Space Arena (Mac + VS Code)

**Цей архів — оновлення, а не окремий Git-репозиторій.** Продовжуй працювати у своїй папці `space-arena-lab-02`, куди додавав ЛР №1–6. ZIP не містить `.git`; теги попередніх лабораторних не змінюються.

## Крок 1. Підготуй папку

Зупини `npm run dev`, якщо він відкритий (`Control + C`), збережи всі файли VS Code (`Cmd + S`) і перевір:

```bash
git status
```

Якщо є незакомічені власні зміни, спочатку збережи їх комітом, а потім виконай наступні команди.

## Крок 2. Додай ZIP

Переконайся, що архів `space-arena-lab-07-update.zip` лежить у `~/Downloads`. У VS Code Terminal з уже відкритої старої папки:

```bash
unzip -o ~/Downloads/space-arena-lab-07-update.zip
node apply-lab07.mjs
```

Скрипт копіює лише нові/змінені файли поверх існуючих, зберігає старий README у `docs/lab-06-readme.md`, не видаляє `.git`, старі тести, ресурси або історію. Після завершення виведе кількість застосованих файлів.

## Крок 3. Встанови нові залежності

```bash
npm install
npx playwright install chromium
npm run format
npm run typecheck
npm run check
```

**Важливо:** саме `npm install` оновлює `package-lock.json` для Vitest, fast-check та Playwright. Додай оновлений lock-файл в коміт, інакше CI з `npm ci` не пройде.

`npm run check`: lint → Prettier → strict TypeScript → старі тести Node → Vitest із порогом coverage 85% для `shared/` → збірка Vite. Якщо щось червоне, не створюй тег, спершу виправ помилку.

## Крок 4. Два браузери та 8 ботів

```bash
npm run dev
```

Відкрий **Local URL, який показує Vite** (зазвичай `http://localhost:5173`; якщо порт зайнятий, відкривай фактичний порт). У двох вкладках зайди під `Player1`, `Player2` в одну кімнату, перевір рух другого корабля та чат.

Для демонстрації 8 ботів відкрий URL Vite з `?bots=8`: наприклад, `http://localhost:5173/?bots=8`. Зайди в кімнату кнопкою Join. Боти розраховуються на Node-сервері. API метрик: `http://localhost:3000/api/perf`.

## Крок 5. Запусти Playwright і профайлер

У **другому терміналі**, зупини або залиш `npm run dev`: Playwright сам запустить сервер, якщо порт 5173 вільний. Якщо порт зайнятий, закрий старий Vite (`Control + C`), щоб Playwright використовував свій тестовий сервер.

```bash
npm run test:e2e
npm run bench:world
```

Для запису 30 сек реального браузерного кадру і CPU-профілю сервер має бути запущений (`npm run dev`) у першому терміналі:

```bash
npm run bench:browser -- after
node scripts/render-flame.mjs bench-out/profile-after.cpuprofile
```

Профілі/кадри з'являться у `bench-out/`. Збережи скрін Chrome DevTools Performance → flame chart в `docs/`. Для об'єктивного **before** використай окрему копію тегу `lab-06`, а не старий README.

Вимір навантаження без браузера:

```bash
npm run bench:clients
```

Дані `bench-out/load.json` та SVG — виміряні на твоєму Mac, їх варто додати у `docs/` перед остаточною здачею. Якщо нові тести не досягли 85% coverage або в Chrome p99 > 16,7 мс — потрібно вказати це в README, а не приховувати.

## Крок 6. GitHub — той самий репозиторій

Після успішних команд, перевірки CI та гри:

```bash
git add -A
git commit -m "Lab 07: Vitest, Playwright, profiling and performance"
git tag lab-07
git push origin main
git push origin lab-07
```

Тег `lab-07` **створюй тільки один раз** після всіх змін. Не використовуй `git push --force`.
