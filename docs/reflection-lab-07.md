# ЛР №7 — Reflection: короткі відповіді для захисту

**1. Чим байткод відрізняється від JIT?** V8 парсить JavaScript, Ignition виконує байткод, а оптимізувальні компілятори для гарячих функцій можуть створити машинний код. Зміни форм об'єктів або типів значень можуть спричинити деоптимізацію.

**2. Що таке hidden class та inline cache?** При послідовному створенні об'єктів однакової форми V8 може повторно використовувати опис розміщення полів. Inline cache запам'ятовує доступ до властивості для знайомої форми. Зміна структури об'єктів у гарячому циклі може позбавити цього виграшу.

**3. Чому GC впливає на плавність?** Багато тимчасових об'єктів збільшують навантаження на збирач сміття. Частина збору може зупиняти JS, тому важливі не тільки FPS, а p95/p99 часу кадру та найдовші паузи.

**4. Навіщо пул куль?** Куля часто створюється та зникає. `ObjectPool` повторно видає ті самі об'єкти, зменшуючи кількість алокацій. При повторному використанні треба повністю переписати всі властивості; інакше залишиться стан попередньої кулі.

**5. Чому серверний крок дорівнює 33,3 мс, а бюджет кадру — 16,7 мс?** Сервер працює на 30 Гц (33,33 мс між кроками), тоді як при 60 Гц один видимий кадр має приблизно 16,67 мс. Це _два різні бюджети_; не можна підмінювати тест серверних тікiв тестом браузерного rAF.

**6. Що перевіряє property-based testing?** Генерує багато валідних і невалідних випадків за властивостями, не лише окремі ручні приклади. `fast-check` зберігає seed і стискає failing-example до мінімального.

**7. Чому під час зіставлення before/after перевіряємо детермінізм?** Оптимізація не може міняти результат гри. Бенчмарк порівнює фінальні authoritative snapshots і переривається, якщо вони різні.

**8. Чому Web Worker не завжди швидший?** Створення воркера, передача повідомлень і копіювання/transfer даних мають ціну. Для 164 зірок одноразова синхронна генерація може бути швидшою. Зберігати роботу у воркері варто лише після вимірювання.

**9. Що означає RSS?** Resident Set Size — фактична резидентна пам'ять процесу; це не те саме, що JS heap. Зростання RSS може включати буфери мережі, код V8, нативні структури.

**10. Де V8 бачить deopt?** Chrome DevTools → Performance / Memory, Node з `--trace-deopt` або CDP Profiler. Треба співставити піки CPU/GC із конкретними гарячими функціями, не робити висновок за однією середньою цифрою.
