# Reflection — ЛР №3: запитання з короткими відповідями

**1. Чому `await loadAll` не блокує інтерфейс, хоча гра не стартує?**

`await` призупиняє лише поточну `async`-функцію `boot`, повертаючи керування event loop. Браузер може рендерити Canvas і обробляти кліки, поки `fetch`, `createImageBitmap` та `decodeAudioData` тривають. Початок симуляції навмисно поставлено після завантаження і натискання Join.

**2. Як працюють стани Promise та поширення помилки?**

Promise починається `pending` і переходить один раз у `fulfilled` або `rejected`. `return` у `.then` передає значення наступній ланці, `throw` переводить downstream Promise у rejected. У `async`-функції помилку з `await` можна перехопити `try/catch`; ми перехоплюємо її у `boot` й показуємо Retry.

**3. Чим відрізняються `Promise.all`, `allSettled`, `race` та `any`?**

`all` очікує всі fulfilled або відхиляється при першій помилці — те, що треба для **всіх** критичних assets. `allSettled` повертає результати навіть помилкових запитів (діагностика). `race` повертає перший settled, включаючи reject; `any` — перший fulfilled, відхиляється `AggregateError`, тільки якщо всі неуспішні.

**4. Навіщо backoff + jitter? Чому не повторювати 404?**

Backoff збільшує затримку між повторами, щоб не посилювати тимчасове перевантаження мережі/сервера. Jitter зміщує синхронні піки клієнтів. 404 вказує, що URL не знайдено: без виправлення URL повтор здебільшого не допоможе, тож `HttpError(404)` одразу зупиняє спроби.

**5. У чому різниця `AbortController.abort()` і `AbortSignal.timeout()`?**

Перший сигнал виникає через логіку програми, наприклад вихід із лобі чи натискання назад. Другий автоматично активується після встановленого часу. Лобі поєднує їх через `AbortSignal.any` для конкретного запиту. Файловий loader аналогічно отримує зовнішнє скасування та timeout на спробу.

**6. Чому Web Audio запускається після Join?**

Браузери обмежують autoplay. Після user gesture створюється/відновлюється `AudioContext`. Асети WAV вже декодовані заздалегідь за допомогою беззвучного `OfflineAudioContext`, тому звук пострілу не потребує повторного мережевого запиту.

**7. Чому у симуляції немає `import '../audio/audio.js'`?**

Game надсилає семантичні повідомлення `fired`, `hit`, `exploded` через переданий `EventTarget`. Звук і, в майбутньому, анімації/HUD можуть незалежно підписуватися; фізика лишається придатною для Node, тестування, серверного перенесення в наступних лабораторних.

**8. Чому не слід очікувати точний порядок між `requestAnimationFrame` і `setTimeout(0)`?**

Таймер і rAF належать різним стадіям browser scheduling, а час frame deadline може змінюватися. Наші п'ять головоломок спеціально реєструють rAF **усередині таймера**, щоб отримати відтворюваний причинний порядок; не виводимо з цього універсального пріоритету timer перед rAF.

**9. Що дає `async *updates`?**

Це асинхронний генератор: DOM-контролер може `for await...of` отримувати події нових кімнат без busy-wait. `finally` знімає event-listener; при виході з лобі `AbortController` припиняє очікування і не допускає витоків.

**10. Що буде, якщо один PNG відсутній, але сім інших файлів завантажились?**

`Promise.all` відхилиться, `boot` скасує ще активні запити і покаже контрольовану помилку на Canvas; симуляція не стартує без критичного ресурсу. Натискання Retry без debug-режиму запускає успішне повторне завантаження.
