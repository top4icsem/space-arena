# Lab 08 — Reflection / відповіді для захисту

**1. Чому Node повинен бути PID 1 у Docker?** Коли runtime запущений без npm-обгортки, Docker SIGTERM доставляється безпосередньо процесу Node. Він встигає перестати приймати нові з'єднання, повідомити клієнтам `shutdown`, надіслати close 1001, дописати NDJSON і завершитися з кодом 0.

**2. /health vs /ready?** Liveness сигналізує, що процес живий; readiness — чи готовий приймати нових гравців. Під час зупинки readiness стає 503, щоб балансувальник перестав надсилати нові з'єднання. HTTP сервер закриває приймання майже одразу після SIGTERM.

**3. Навіщо звіряти Origin при WebSocket handshake?** Браузер автоматично надсилає Origin, і без перевірки стороння сторінка може відкривати WS до нашого сервера. Це не замінює автентифікацію, а лише обмежує дозволені вебсайти. Поза браузером Origin можна підробити, тому залишаємо rate limits, перевірку пакета й сервісну авторизацію за потреби.

**4. Чому не можна просто додати другий процес Node?** RoomManager і SharedWorld зберігають стан гри в пам'яті окремого процесу. Двоє гравців однієї кімнати, спрямовані на різні інстанси, бачитимуть різні світи. Для горизонтального масштабування потрібні room affinity/sticky routing або зовнішній синхронізований стан.

**5. Навіщо двоетапна збірка Docker?** TypeScript/Vite/ESLint/Vitest потрібні лише для збірки. У фінальний runtime копіюються статичний клієнт, TS сервер (Node 22 strip types), shared runtime й production node_modules без dev-інструментів. Це скорочує attack surface й розмір.

**6. Чому WSS обов'язковий?** HTTPS-сторінка повинна відкривати WebSocket через TLS (`wss://`), інакше браузер заблокує mixed content. Проксі термінує HTTPS та коректно передає HTTP Upgrade на Node.

**7. Чому метрики p99 важливіші за середнє?** Рідкісний довгий кадр або тик помітний як ривок, хоча середня тривалість може залишатися низькою. Результати клієнтського Chrome frame p99 і серверного world step p99 — не одна й та сама величина.

**8. Які обмеження є після релізу?** Один процес Node, короткочасний state in memory (втрачається при рестарті), proxy IP rate-limit без довіреного header, PWA вимагає мережу, високі навантаження потрібні окремі виміри. Це свідомо спрощений навчальний проєкт.
